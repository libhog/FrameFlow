# FrameFlow Studio UI 디자인 표준

## 1. 제품 인상

FrameFlow는 생성형 영상 작업을 오래 관리하는 제작 도구다. 화면은 장식보다 **현재 위치, 다음 행동, 생성 상태, 미디어 비교**를 먼저 보여준다.

- 톤: 차분한 스튜디오, 선명한 상태 표시, 가벼운 신선함
- 금지: 과도한 그라데이션, 3D 버튼 그림자, 10px 미만 본문, 영문 대문자 장식의 남용
- 핵심 원칙: 한 화면에 하나의 주 작업, 한 영역에 하나의 강조 버튼

## 2. 기존 화면 평가

| 화면 | 직관성 문제 | 가독성 문제 | 개선 기준 |
|---|---|---|---|
| 프로젝트 목록 | 커버 이미지와 프로젝트 정보의 관계가 약하고 관리 버튼이 커버 위에 흩어짐 | 설명·경로·모델이 지나치게 작음 | 커버 16:9, 제목→설명→상태→경로 순서, 관리는 단일 `···` 메뉴 |
| 프로젝트 상세 | 씬/컷/생성 버튼이 같은 시각 무게로 반복되어 어디서 시작할지 불명확 | 카드 내부 8~11px 텍스트와 좁은 열 때문에 줄바꿈·세로 글자 발생 | 씬 헤더와 컷 작업을 분리하고 14px 이상, 카드 최소 폭과 버튼 우선순위 고정 |
| 씬·컷 편집 | 긴 한 화면 안에 FLF, 프롬프트, 분석, 결과가 연속되어 탐색 비용이 큼 | 창 폭이 좁고 중첩 스크롤이 발생 | 화면 92% 작업창, 명확한 섹션 번호, FLF→프롬프트→분석→영상 결과 순서 |
| 메타 프롬프트 | 한·영 필드와 분석 결과가 동일한 강조도로 반복됨 | 라벨·본문 크기가 불균일하고 긴 JSON과 최종 프롬프트가 과밀 | 한국어 편집/영문 원본을 색·배경으로 구분, 결과는 카드 단위, 하단 적용 버튼 고정 |
| 생성 큐 | 상단 요약 수치와 우하단 진행창의 수치 관계가 모호함 | 상태 배지가 작고 작업명보다 기술 정보가 먼저 보임 | 단일 상태 체계, 작업명 우선, 진행/성공/실패 색상과 상세 사유 일관화 |
| 설정 | 서비스 설정이 긴 카드로 이어져 연결 상태와 필수 입력의 우선순위가 약함 | 도움말과 입력값의 대비가 낮음 | 카테고리 내비게이션, 연결 상태 헤더, 입력 44px, 도움말 13px |

### 개선안 평가 (5점 기준)

| 화면 | 직관성 | 가독성 | 판정 근거 |
|---|---:|---:|---|
| 프로젝트 목록 | 4.5 | 4.5 | 프로젝트 제목·설명·상태의 순서가 고정되고, 커버 전체가 진입점이며 관리는 `···`로 분리됨 |
| 프로젝트 상세 | 4.2 | 4.4 | 씬 작업과 컷 작업이 각 헤더에 묶이고, 카드 최소 폭으로 세로 글자와 과도한 줄바꿈을 방지함 |
| 컷 편집 | 4.4 | 4.6 | 화면 94% 작업창, FLF→연출/카메라→전환/요소→결과 순서가 유지되며 단일 세로 스크롤만 사용함 |
| 생성 큐 | 4.6 | 4.5 | 작업명 우선, 상태·진행률·실패 수치를 같은 체계로 표시하고 우하단 진행창은 현재 배치 요약만 담당함 |
| 설정 | 4.2 | 4.4 | 범주 내비게이션과 설정 카드가 분리되고 입력·도움말의 최소 크기와 대비가 고정됨 |

점수는 대표 화면을 1280px 폭에서 렌더링하여 다음 행동을 3초 안에 찾을 수 있는지, 본문을 확대 없이 읽을 수 있는지, 정보가 세로로 끊기거나 중첩 스크롤이 생기는지를 기준으로 평가한다.

## 3. 타이포그래피

- 기본 글꼴: `Pretendard`, `Noto Sans KR`, `Segoe UI`, sans-serif
- 화면 제목: 32px / 700 / 줄높이 1.2
- 섹션 제목: 20px / 700
- 카드 제목: 16px / 700
- 본문·입력: 15px / 400~500 / 줄높이 1.65
- 보조 정보: 13px / 500
- 상태·태그: 12px / 700
- 절대 최소 크기: 12px. 파일명처럼 밀도가 필요한 정보만 12px 허용

## 5. 공간과 형태

- 기본 간격 단위: 4px
- 화면 좌우 여백: 32px, 넓은 화면 40px
- 카드 내부 여백: 20~24px
- 필드 간격: 16px
- 카드 반경: 16px, 입력·버튼 반경: 10px
- 기본 그림자: `0 8px 28px rgba(25, 51, 43, .06)` 한 종류
- 클릭 영역: 최소 높이 40px, 주요 버튼 44px

## 6. 버튼 계층

1. Primary: 현재 영역의 확정·생성 행동. 코랄 단색, 한 영역에 하나
2. Secondary: 테스트·복사·가져오기. 흰색+테두리
3. Tertiary: 보기 전환·접기·더보기. 배경 없는 텍스트/아이콘
4. Danger: 취소·삭제. 빨간색은 확인 단계에서만 강하게 사용

동일 행에서는 `Secondary → Primary` 순으로 배치하고, 삭제는 `···` 안에 둔다.

## 7. 화면별 정보 구조

### 프로젝트

`프로젝트 커버 → 제목/설명 → 씬·컷·모델 → 최근 수정 → 폴더 경로`

### 프로젝트 상세

`프로젝트 요약 → 전체 생성 → 프로젝트 설정 → 씬 헤더 → 컷 카드`

컷 카드는 `FLF 미리보기 → 선택 영상 → 상태/모델/길이 → 테스트/생성/결과` 순서를 유지한다.

### 씬·컷 편집

1. 기본 정보
2. FIRST / LAST Frame
3. 연출 의도와 한·영 프롬프트
4. FLF 분석과 메타 프롬프트
5. 선택 영상
6. 생성 영상 기록

### 생성 큐

상단 요약과 우하단 도크는 같은 상태 정의를 사용한다: `진행 중 / 대기 / 성공 / 실패·중단`.

## 8. 직관성 검증 체크리스트

- 5초 안에 현재 프로젝트·씬·컷 위치를 말할 수 있는가?
- 다음에 눌러야 할 주요 버튼이 하나로 보이는가?
- 테스트와 최종 생성이 색과 문구로 구분되는가?
- 선택 영상과 생성 이력이 한눈에 구분되는가?
- 실패 사유를 한 번의 클릭으로 볼 수 있는가?
- 드래그 가능한 곳에 핸들과 마우스 커서가 있는가?

## 9. 가독성 검증 체크리스트

- Windows 125%·150% 배율에서 12px 미만 텍스트가 없는가?
- 한국어 본문 줄높이가 1.55 이상인가?
- 긴 파일명·경로는 말줄임과 전체 툴팁을 함께 제공하는가?
- 좁은 폭에서 텍스트가 한 글자씩 세로로 깨지지 않는가?
- 중첩 스크롤은 씬 편집 모달 한 곳으로 제한되는가?
- 키보드 포커스가 3px 테두리로 보이는가?
